# 油站网点地图管理

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Element Plus、Pinia、Leaflet
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- E2E：`npm run e2e`（Playwright + Chromium，首次需 `npx playwright install chromium`）

这是一个功能最小闭环前端项目，数据默认保存在浏览器 localStorage 中，方便后续扩展接口、权限、图表或地图能力。

## 模块

### 油站资料
维护油站名称、区域、库存摘要、负责人、营业状态与备注，支持区域过滤、状态流转和迷你统计图。
数据存储键：`hxwlfront-21-station-map`。

### 区域补货调度
按区域 + 计划日期生成补货建议：

1. **缺口计算**：分油品按「库容 − 当前库存」计算缺口，按需求优先级（高 > 中 > 低，同级按缺口率）排序。
2. **任务合并**：同区域任务按油品类型贪心装箱到有限车队（汽油车 3 / 柴油车 2），best-fit 合并，逐站排到站时刻（含路程/卸油时长）。
3. **三重校验**：车辆容量、站点收货时段、油品兼容；同时检查同车时刻重叠和跨在审/锁定计划占用。车辆容量不足时缺口进入「无法满足」面板并说明原因。
4. **人工调整**：改数量、改到站时刻、改派车辆、把站点任务移动到其他车（同站同油品自动合并，不产生重复班次）；剩余缺口、待执行班次、无法满足站点实时重算。
5. **状态机**：草稿 → 提交评审 → 评审通过锁定；待评审可撤回、已锁定可改单，两者都回到草稿；已有执行登记的锁定计划必须先撤销执行才能改单。所有动作写操作日志（操作人 + 时间 + 说明）。
6. **并发防护**：计划带乐观版本号（CAS）+ 同计划操作互斥锁；跨标签页通过 storage 事件同步。重复生成/重复提交幂等，不会产生重复计划或重复班次。
7. **执行与回看**：锁定后逐站登记实收量、差异原因（足额/运输损耗/计量差异/拒收）、说明与完成时间；实收回补罐体库存影响后续计划缺口；全部完成自动关单；回看表对照生成时缺口、已安排、剩余缺口、实收、差异原因、完成时间。

调度模块使用独立 localStorage 键（`hxwlfront-21-scheduling-profile` / `-vehicles` / `-plans`），不影响油站资料数据。

## E2E 场景（e2e/ 目录）

- `normal.spec.ts`：生成 → 评审锁定 → 逐站登记实收（含运输损耗差异）→ 自动完成 → 回看
- `conflict.spec.ts`：超容量/错时段/错油品阻断提交、重复生成幂等、车队容量不足、跨标签页并发改派无重复班次
- `revoke.spec.ts`：撤回、改单、已执行后禁止改单、撤销执行、完成后撤销
- `reschedule.spec.ts`：减量/移除任务的实时缺口与未满足站点重算、跨车移动不产生重复行
- `station-profile.regression.spec.ts`：油站资料页新增/过滤/流转/删除/刷新持久化回归
